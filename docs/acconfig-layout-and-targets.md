# ACConfig 布局与队内目标选择

## 页面行为

- Operator 下的账户选择器负责切换已保存账户；新增账户与账户管理从控制面板的“账户与令牌”进入。
- 桌面顶栏与导航组成自然高度的吸顶区域，空间不足时换行；手机使用紧凑顶栏与底部导航。长 UID、昵称可查看完整提示。
- 三种主题共用表面、文字和边框变量。禁用列表默认收起，展开内容最多占 `min(360px, 50dvh)`，盟约名称旁不再显示首字母圆标。
- 玩家信息以紧凑行显示。“赛季开发工具”位于管理工具末尾，默认收起，展开后才加载悬赏目录。

## 操作目标

“作用玩家”共用于金币、生命、盟约层数、添加棋子与悬赏。任何队员可选择同队未淘汰玩家，包括暂时断线的玩家；管理员保留跨队能力。首次进入优先选择本人，否则选择第一位可用玩家。目标离队或淘汰后清空选择，不自动改为另一名玩家。

切换账户或队伍时重新建立工具状态；切换目标时清理输入和反馈。旧状态请求与旧目标操作的迟到响应不会覆盖当前页面。回合、阶段与解散仍为队伍操作，移出玩家仍使用现有同队权限。

服务端配套提交：`aa6cfee`。`POST /cheat/action` 的金币、生命、盟约层数和添加棋子操作支持可选顶层 `targetUserId`；悬赏继续使用 `value.targetUserId`。省略目标兼容旧调用。服务端校验队伍访问权限、目标归属和淘汰状态，悬赏的回合、路线及奖励规则沿用既有实现。完整说明见服务端 `api-docs.md`。
